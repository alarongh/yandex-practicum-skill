# Проверка и сдача проектов

- Сверь условия конкретного проекта и границы уже полученного подтверждения. Найди его репозиторий и рабочую ревизию. Сравни файлы с исходным шаблоном, если это позволяет сразу определить объём работы.
- Проверяй проект по нормальному пути запуска. При недоступности видео-API во второй практике используй отдельную локальную копию и предоставленный локальный API или тестовые данные. Сохрани версию для сдачи с конфигурацией из задания. Локальная проверка подтверждает поведение с этими данными.
- При ошибке ревью начни с текста конкретного провалившегося теста. Например, проверка «Посмотри в окно» требовала файл README.md в корне и прямой URL репозитория одной строкой. Применяй этот формат по требованию, которое видно в текущем задании или в ответе проверки.
- Если отправка входит в поручение, сверь опубликованную ревизию и результат GitHub Actions, затем открой «Ревью» в Практикуме. «GitHub настроен» означает, что репозиторий подключён. «Задание отправлено» подтверждает отправку. Приёмку подтверждают «Проверено» или сообщение «Задание принято».
- При статусе «Тесты не пройдены» возьми точное сообщение из «Ревью». После исправления и публикации, если поручена повторная сдача, используй «Отправить новую версию» и «Проверить задание», когда они доступны. Дождись итогового статуса. Формулировки могут отличаться между проектами.
- Если поиск вкладки по URL дал тайм-аут или несколько совпадений, выбери уже открытую вкладку по выданному браузером ID и проверь её заголовок и состояние.
